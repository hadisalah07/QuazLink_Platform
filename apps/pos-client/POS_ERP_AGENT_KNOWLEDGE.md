## 📌 المعايير الهندسية الثابتة (Architectural Invariants)

1. **معيار الطباعة الحرارية الصاروخية (Canvas-to-Raster 1.8ms Pipeline):**
   - **المشكلة المزمنة**: تشويه وتقطيع الحروف العربية في الطابعات الحرارية ESC/POS عند إرسال نصوص مباشرة.
   - **المعيار الإلزامي**:
     1. تصيير الفاتورة كـ HTML/CSS خفيف محلياً مع دعم كامل للخطوط العربية.
     2. تحويل الـ HTML إلى Canvas، ثم توليد صورة أحادية البت (1-Bit Monochrome Bitmap).
     3. أبعاد الكانفاس الثابتة:
        - **طابعات 80mm**: عرض ثابت **`576px`** (72mm منطقة طباعة / 203 DPI).
        - **طابعات 58mm**: عرض ثابت **`384px`** (48mm منطقة طباعة).
     4. إرسال الصورة كأمر نقطي قياسي `GS v 0` أو `ESC *`.
     5. زمن التحويل الكامل يجب ألا يتجاوز **50ms إلى 100ms** لضمان سرعة خروج الفاتورة.
   - **درج النقدية**: إرسال النبضة القياسية `ESC p 0 25 250` عبر منفذ الطابعة RJ11 فور انتهاء الطباعة.

2. **معيار الفاتورة والإيصال الإلكتروني المصري (ETA 2026 Mandate):**
   - توليد الـ QR Code المشفر بتقنية TLV (Tag-Length-Value) Base64:
     - Tag 1: اسم الشركة / المتجر (Seller Name)
     - Tag 2: الرقم الضريبي (Tax Registration Number)
     - Tag 3: تاريخ وتوقيت الفاتورة (Invoice Timestamp)
     - Tag 4: إجمالي الفاتورة شاملاً الضريبة (Total Amount with VAT)
     - Tag 5: قيمة ضريبة القيمة المضافة 14% (VAT Amount)
   - يتم طباعة الـ QR Code في أسفل الفاتورة الحرارية ليتم مسحه وتوثيقه لدى مصلحة الضرائب المصرية فوراً.

3. **معيار التوافق المزدوج (Dual-OS Guarantee: Windows 7 + Windows 10/11):**
   - دعم كامل لأجهزة نقاط البيع القديمة العاملة بـ POSReady 7 أو Windows 7 SP1 (بمعالجات Celeron ورام 2GB).
   - استخدام Keycodes قديمة وحديثة لاختصارات الكاشير السريعة.
   - حظر استخدام أي مكتبات أو Node APIs تتطلب Windows 10+ حصراً.

## 🧠 سجل الدروس المستفادة والأخطاء المحلولة (Historical Lessons & Solutions)

### الدرس #1: فحص الـ Syntax الإلزامي للواجهة (`node -c`)
- **المشكلة**: خطأ في صياغة JavaScript في `apps/pos-client/src/ui/app.js` أدى إلى تجميد شاشة الكاشير وظهور شاشة بيضاء دون أخطاء في الـ Node Backend.
- **الحل الجذري المتبع**:
  إدراج خطوة فحص إلزامية في بروتوكول البناء:
  ```bash
  node -c apps/pos-client/src/ui/app.js
  ```
- **القاعدة المستفادة**: لا يتم تسليم أي تعديل في واجهة الكاشير دون نجاح أمر الفحص اللغوي.

### الدرس #2: الترتيب الذري الصارم لرفع التحديثات (Atomic Release Pipeline)
- **المشكلة**: أجهزة الكاشير دخلت في حلقة تحديث لا نهائية (Infinite Loop)؛ التطبيق يكتشف وجود إصدار أحدث على السيرفر وعند محاولة التحميل يجد ملف قديم لم يكتمل رفعه بعد.
- **الحل الجذري المتبع**:
  تطبيق بروتوكول الترتيب الذري الإلزامي:
  1. بناء `QuazLink-POS-Setup.exe` و `QuazLink-POS-Patch.zip`.
  2. رفع الملفات إلى مسار التنزيلات على السيرفر `/data/downloads/`.
  3. التحقق من سلامة التحميل عبر `curl -I`.
  4. **فقط بعد اكتمال الرفع والتحقق بنجاح 100%**، يتم تحديث متغيرات `POS_LATEST_VERSION` في الـ API.

### الدرس #3: منع تلف قواعد البيانات (ACID Transactions)
- **المشكلة**: انقطاع الكهرباء المفاجئ أثناء عملية الدفع قد يؤدي لخصم الرصيد من المخزن دون تسجيل الفاتورة أو العكس.
- **الحل الجذري المتبع**:
  تغليف عمليات البيع وتعديل المخزون في معاملة ذرية متكاملة عبر `db.transaction()` مع تفعيل SQLite WAL Mode لضمان التزامن السريع والآمن.
